### Problemas encontrados
#### 1. Ano `0000` é rejeitado sem que a spec diga nada a respeito — severidade BAIXA
- **Regra afetada:** RN-002 ("datas válidas `AAAA-MM-DD`")
- **Evidência:** `src/reembolso/entrada.py`, `_data`. `"0000-01-01"` casa com a regex, mas `date.fromisoformat` lança `ValueError` (o ano mínimo do Python é 1), e o resultado é `ErroDeArquivo`. A spec não diz se o ano 0000 é uma data válida.
- **Impacto:** só um `periodo.inicio`/`fim` com ano `0000` vira erro de arquivo. Não há teste para isso. Na prática esse caso não deve acontecer e não muda nenhum resultado previsto pela spec.
- **Recomendação:** nenhuma correção obrigatória. Se quiserem fixar o comportamento, registrem na spec. Por ser tão improvável, não coloco o caso como decisão bloqueante.

### Cobertura
- **Regras testadas:**
  - RN-002 (erro de arquivo do cabeçalho, definição de espaço em branco, `id` `"-"` válido, campos extras ignorados) → `tests/test_rn002_validacao_da_entrada.py`.
  - RN-013/D-006 ponto 5 → os três testes de chave repetida no mesmo arquivo.
  - DT-003 → regex ASCII mais `fromisoformat`, e espaço em branco = `isspace()` sem U+001C–U+001F. Conferi esta última na prática: no Python 3.12 (Unicode 15.0), o conjunto de `isspace()` menos U+001C–U+001F é exatamente o conjunto White_Space do Unicode, sem sobras nos dois sentidos.
